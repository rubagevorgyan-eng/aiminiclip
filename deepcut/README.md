# DEEPCUT

*The deeper your knowledge, the deeper you go.*

A browser trivia game: seven open questions, 25 seconds each. Any correct answer counts, and rarer answers dig deeper (Coal 10m up to Diamond 100m, max 700m). Daily Dig gives everyone the same seven questions each UTC day. Unlimited Dig is random, as often as you like.

Static site: Vite + React + TypeScript, no backend, no accounts. Progress is stored in the browser's localStorage.

## Install and run

Requires Node 22.6+ (tests use Node's built-in TypeScript stripping; Node 24 recommended).

```bash
npm install
npm run dev        # http://localhost:5174
npm test           # unit tests (node:test, no extra deps)
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ at http://localhost:4174
```

## Deploy

`dist/` is a plain static site with relative asset paths, so it works at a domain root or in any sub-folder.

- **Vercel:** import the repo, set the project's Root Directory to `deepcut`. `vercel.json` sets the build (`npm run build`), output (`dist`) and long-lived caching for hashed assets.
- **Netlify / Cloudflare Pages / GitHub Pages:** build command `npm run build`, publish directory `deepcut/dist`.
- **Recess site (this repo):** `npm run publish:site` builds and replaces `../games/deep-cut/` with the new build. Commit that folder; Netlify serves it at `/games/deep-cut/`.

After deploying, change `og:image` and `twitter:image` in `index.html` to the absolute URL of `og-image.jpg` (some link previews ignore relative image URLs).

## Question bank

The game loads its questions at runtime from `public/bank/`: `index.json` (id, text, category, difficulty, family, answer count) and one `q/<id>.json` per question with its answers. Only the seven questions of a dig are fetched.

The bank is generated by `scripts/bank/build.py` (Python 3, no dependencies, needs `curl`):

- **Wikidata families** (`scripts/bank/families.py`): each family is a question template plus a SPARQL pattern, e.g. "Name a film directed by {label}" over the directors of the most-linked films. Answers are the matching items with their English labels and aliases. Wikidata is CC0; every question records its source and retrieval date.
- **Rarity** comes from each answer's Wikipedia sitelink count (how many language editions cover it), relative to the question's best-known answer: the most covered answers are Coal, the least covered Diamond. It is a popularity proxy, not player statistics.
- **Editorial sets**: the hand-written questions in `src/data/questions/*.json` and the complete fixed sets in `families.py` (`STATIC`) are included as-is.

```bash
python3 scripts/bank/build.py --batch 1      # build every family in batch 1 (resumes: finished families are skipped)
python3 scripts/bank/build.py --family mov-director --force   # rebuild one family
python3 scripts/bank/build.py --write        # merge built families + editorial sets into public/bank
npm test                                     # integrity: categories, rarities, aliases, sources, daily variety
```

Built families are saved in `scripts/bank/built/` (committed) and query results cached in `scripts/bank/.cache/` (ignored), so rebuilding never re-downloads finished work.

Editorial question format (`src/data/questions/<category>.json`):

```json
{
  "id": "geo-borders-china",
  "text": "Name a country that borders China.",
  "category": "Geography",
  "difficulty": "medium",
  "answers": [
    { "name": "Russia", "rarity": "common" },
    { "name": "Myanmar", "aliases": ["Burma"], "rarity": "rare" }
  ],
  "reject": ["Japan"],
  "ignore": []
}
```

- `rarity`: `common`, `uncommon`, `notable`, `rare`, `legendary`, `mythic` (Coal to Diamond).
- `aliases`: other spellings and names. Case, accents, punctuation, "the", "St"/"Saint" and Roman numerals are already handled; small typos are accepted on answers of 7+ letters.
- `reject`: wrong answers never accepted; `ignore`: words dropped before matching.

Every game (Daily and Unlimited) mixes at least 5 categories, with one everyday/general question, one geography/history question, one science/nature question, at most one word question, no repeated template and at least one non-easy question (`pickGame` in `src/data/selection.ts`). The Daily Dig is seeded by `BANK_VERSION` and the UTC date, so changing the bank changes future dailies; past results keep their own question ids and stay viewable. Deploy bank changes near 00:00 UTC.

## Known limitations

- Rarity is editorial judgment, not real player statistics. There is no backend, so no global leaderboards, accounts or cross-device sync.
- Progress lives in one browser; clearing site data resets it. Only a finished Daily Dig is recorded, once per browser per day; leaving or reloading mid-dig restarts from the home screen, so an unfinished daily can be replayed.
- Generated answer lists are only as complete as Wikidata: a correct answer missing there is rejected. Sitelink counts measure coverage, not what players actually type.
- Bounded editorial lists are complete as of 2025; time-sensitive questions say "up to 2025" and will need refreshing.
- On iPhone, keyboard handling relies on the Visual Viewport API; tested in browser emulation, not on a physical device.
- Sounds are synthesized; their balance was verified by instrumentation, not by ear on many devices.
- Fonts load from Google Fonts; offline, system fallbacks are used.
